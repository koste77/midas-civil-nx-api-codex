# 故障处理与恢复

以下现象可作为诊断线索；不预设每次任务都会出现，也不自动执行重启或删除。

| 现象 | 核查与处理 |
|---|---|
| GET 超时或未连接 | 检查 API Settings 的 Connected、Base URL 和环境变量是否已设置；不输出值。冷启动耗时因安装而异，超时按实际环境设置。GET 有限重试后停止 |
| HTTP 200 但未分析 | 检查 error、success、status/result 和完成消息，保留脱敏响应；不能继续把旧结果计入本轮 |
| 写入或分析请求超时 | 视为状态未知。检查进程、弹窗、数据库回读、结果产物；分析仍在进行时继续等待，避免再启动一次 |
| POST/PUT 失败 | 检查当前 ID、表权限、字段类型、引用及参数范围；先回读，不能直接把 PUT 改 POST 重试全部 |
| 更换拓扑后分析拒绝 | 检查旧车道、横梁组、单元、阶段和荷载引用。先修复依赖，再分析 |
| Open 卡住或弹未保存提示 | 准备阶段 PUT 也会使文档变脏，缓存命中并不会替软件保存。先保存任务副本，再切换；不能盲点丢弃 |
| /doc/export 耗时异常 | 不重复堆叠请求。已有保存模型和结果时，按需 GET 核心表可作有限快照；记录实读、继承、缺失，不能称原生全库导出 |
| 保存重开后显示名称变化 | 区分标签编码与物理字段。仅对已核实的精确差异记录例外，不全局忽略所有名称/字符串差异 |
| 原文件散列发生变化 | 核查另存是否触发源文档重序列化。先保护变化前后文件和数据库证据，核对内容；恢复原件前确认没有用户新修改 |
| 软件失去连接或需重启 | 优先界面/API重连。需要关闭进程时，先核实任务拥有的PID、可执行文件和活动文档已保存；不按进程名批量结束其他会话 |

请求失败记录至少包括方法、端点、耗时、状态、对应任务与参数身份；不包含认证头。标准客户端会保存脱敏调用元数据，不自动保存服务端原文。

单次分析的等待可由短间隔状态检查组成，避免长时间失去进度反馈。等待本身不产生再次求解的授权，也不代表任务已经失败。恢复后先验证同一工作模型，再决定重放未完成操作。

已有用户授权和任务副本保护足以完成常规可逆工作时继续执行，不额外要求重复确认。若遇到未保存的其他文档、无法确认所有权的进程或超出任务范围的删除，应保留现场并说明所缺信息。

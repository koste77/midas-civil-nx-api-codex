# 参数化建模与分析流程

## 建模准备

已有模型先保护源文件、建立任务副本及冻结基准；新建模型先用已核实的最小记录模板。坐标生成和连接表在本地完成，API 只上传通过拓扑/引用检查的数据。不要每增加一个节点就请求一次。

本地检查至少覆盖实际任务相关项：节点唯一/重合与构件连接、材料截面引用、局部轴、单位、边界稳定、刚性连接拓扑、荷载方向和总力/力矩。梁壳组合时列明实体、虚拟构件、偏心、质量和刚度分工，检查重复贡献。

修改拓扑可能使移动荷载车道、横梁组、施工阶段或组合失效。先判断保留功能并更新引用；若在已授权的专项副本中移除无用旧工况，应记录范围，不能默默更改通用设计模型。

## 参数登记与随附生成器

参数登记说明：物理机制、空间分组、字段、基准、单位、取值依据、联动项与不变量。E 缩放可能同时改变 EA、EI、GJ 和 GA；截面倍率也不自动等于材料模量。质量若固定须检查 DEN、WGT_SF 和恒载转质量设置。

`scripts/midas_api.py plan` 只支持 **固定拓扑下已有数值字段** 的 set/scale 更新，不创建材料、截面、网格或分析模型，不调用 API。复杂构造或界面需要任务专用生成逻辑。

输入 baseline.json 为已冻结的表名到编号记录的映射，例如 `{"SECF":{...},"MATL":{...}}`；如果来自全库 DBG 导出，应先显式提取 DBG 内所需表。

parameters.json 示例：

```json
{
  "girder_eiy": {
    "bounds": [0.9, 1.1],
    "targets": [
      {"table": "SECF", "id": "101", "path": ["ITEMS", 0, "IYY_SF"], "mode": "scale"}
    ]
  }
}
```

values.json 示例：

```json
{"girder_eiy": 1.05}
```

101 只是说明编号，范围也仅演示输入格式，不能当工程建议。先从实际 GET 记录确定 ID、ITEMS 索引及分组；若变截面需要两端同步，应明确添加已经核实的 J 端目标。

每个 scale 均使用冻结字段乘参数，set 表示直接设置该数值。生成器拒绝缺失字段、重复目标、越界、非有限数、未知参数；输出完整目标记录的 Assign 数据块及输入散列。重复生成同一参数应给出相同结果，输入基准不得改变。

输出中的散列仅标识这次离线参数生成，**不是完整分析缓存身份**。分析身份另需包含下述模型、荷载和恢复设置。

## API 执行顺序

1. 确认当前为任务副本，GET 基准表；保存冻结副本和源文件散列。
2. 本地生成本轮完整记录。根据当前已有编号选择 POST/PUT，只上传必要差异，分块大小按实际性能决定。
3. GET 回读参数目标及不变量。浮点比较采用符合字段尺度的容差；不能统一放过所有字符串或材料类型差异。
4. 保存任务模型。记录模型身份、参数、单位、荷载/质量情景、分析设置、结果提取配置和恢复版本。
5. 检查缓存身份及原始产物完整性；完整命中可复用结果，但不能据此认定软件当前也处于该参数状态。最终交付或下一次增量修改前仍应回读/恢复实际状态。
6. 若需实际分析，先记录预算、求解前产物状态和开始时间，调用一次分析并检查新鲜结果。提取必要表，不在每一轮全库导出。
7. 本轮原始产物齐全且核验成功后提交成功检查点；失败/状态未知分别记录，不写成成功缓存。

写入与分析示意，具体 updates 已通过任务检查；客户端不会替调用者检查当前打开的是哪个模型：

```python
client = MidasClient()
for table, body in plan["updates"].items():
    # 这里只示意已核实为现有编号的 PUT；新编号需按表契约 POST。
    client.request("PUT", "/db/" + table, body)
    actual = client.request("GET", "/db/" + table)
    # 由任务脚本对照目标及不变量，不省略实际检查。
client.request("POST", "/doc/save", {})
answer = client.request("POST", "/doc/anal", {}, timeout=240)
require_analysis_complete(answer)
# 此后仍需核查求解器消息与新鲜结果，才能归档成功。
```

脚本 API 导入时，将本技能 scripts 目录加入 sys.path 或在任务项目中采用明确的模块导入方式；避免把用户环境内旧版本同名模块误导入。

## 物理口径

- 仅进行线弹性静力时，质量不直接约束刚度。动力频率同时受刚度、质量、边界和模态对应影响。
- 静力荷载试验比较采用车辆增量；材料密度、构件自重、二期恒载和荷载转质量需有清单，避免重复计入。非线性分析用同一物理模型的一致状态路径。
- 预应力可能影响裂缝、应力及几何刚度，不能直接表述为把混凝土 E 提高一个倍率。
- 梁壳模型的新增板、旧翼缘、横梁/横隔及刚臂不能重复计算同一质量或刚度。不同层的实际厚度、传荷扩散和结构刚度分别定义。
- 应变按真实测点、局部轴、形心、偏心及轴力/两向弯矩恢复。检查截面缩放是否被所用应力结果正确反映。

以上按当前任务使用，不把某座桥的材料、铺装厚度或测点作为默认值。

## 批量扫描与反演

先登记实际正演预算、检查点和停止条件，再开展计算。优先复用已验证基准；少参数机制检验通过后再逐步增加独立参数。参数数量小于观测数不证明可辨识。

缓存身份应包括：源模型或完整有效数据库散列、参数映射/向量、荷载、质量、单位、求解器/分析设置、结果恢复与模态参考版本。观察目标和权重变化时，只有正演身份相同才复用原始 FE 响应，并重新计算目标函数。

差分步长结合参数尺度、结果打印精度和真实响应确定。低灵敏度方向与近似 Jacobian 失真不能靠无休止刷新解决；先核对物理假设及预算。真实末点复算、局部收敛检查、可辨识性和留出预测分别评价。

恢复优化需同时恢复选点、Jacobian 中心/版本、信赖域、边界、权重和预算计数；若仅恢复缓存而重新初始化算法，应明示为新搜索，不称续算。保存/回读成功后再更新相应状态。

## 最小交付

工作模型、源模型身份、参数映射和实际接受值；必要结果原表和单位；参数/质量/力平衡核对；计算次数及失败原因；复现命令和检查点。根据任务给出误差或参数结果，明确未完成的物理验证，不把“文件一致”当成“校准成功”。
